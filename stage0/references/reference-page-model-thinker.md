# The Model Thinker

Source: Scott E. Page. Conceptual notes restored and revised from the repository's
historical Stage 0 corpus. These notes summarize the resource; they are not exact
quotations or a fresh verification of the source text.

The current protocol is [Stage 0](../SKILL.md). This resource is optional; it
does not add a mandatory method sequence or a new solver capability.

## Concepts available for investigation

Models can help reason, explain, design, communicate, act, predict and explore
(REDCAPE). The intended use helps choose the necessary detail and acceptable limits.
Explicit assumptions make a proposal easier to inspect, but do not make errors
cheap or guarantee that the investigation will correct them.

Several accounts may explain different parts of a situation. Record whether they
compete, complement one another, use alternative boundaries, or have an unresolved
relationship. Their coexistence need not be a temporary failure to pick a winner.
A simple, sufficiently specified comparison needs no extra account merely for variety.

Dynamic descriptions can raise questions about equilibrium, cycles, randomness and
path dependence. These concepts are prompts for choosing an appropriate analysis,
not an exhaustive classification that every case must pass through. A model's
assumed behavior does not establish the corresponding behavior of the real system.

Lyapunov methods and Markov-chain analysis are examples of formal tools with their
own hypotheses. Failure to find a suitable certificate does not establish absence
of an equilibrium. Visual trends, a named framework and repeated observations do
not constitute a formal stability proof. Suspected heavy tails likewise require
appropriate analysis rather than a diagnosis based only on a plot.

## Current Stage 0 application

Select methods from the question and available model, not from a fixed book order.
Record applicability and its reason. For stability work specify the dynamic model,
method, assumptions and result dependencies. The library does not verify formal
stability certificates; external work remains external_unverified here.

Before collecting evidence, describe possible findings and their implications,
including an inconclusive finding. An observation may be exploratory or descriptive
when no feasible discriminating test is available. Do not promise that one more
measurement will necessarily resolve the accounts.

A model that cannot answer a question invites a boundary or method revision. It
does not prevent the user from asking the question. Preserve unresolved evidence
and return to dependent analyses when the boundary or measurement changes.
